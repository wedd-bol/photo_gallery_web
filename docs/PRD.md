## 1. 产品定位与已知条件

**把个人摄影作品集做成一座可以探索的线上摄影展：第一眼有记忆点，继续浏览时照片清楚、操作顺畅。**

用户已确认主要场景为「个人摄影作品展示」。目标不是管理全部摄影原片，而是展示经过选择、排序和修图的作品，并通过一个网址分享。

目前仓库只有 README 和仓库规则，尚无前端应用、技术框架和照片素材。本次交付为 PRD，不安装依赖、不生成页面、不发布网站。

## 2. 用户、目标与成功标准

### 2.1 主要用户

| 角色 | 主要诉求 | 核心任务 |
| --- | --- | --- |
| 摄影作者 | 有个人风格，更新作品方便，展示完整系列 | 新增作品、组织系列、设置封面和排序 |
| 首次访问者 | 很快知道作品风格，愿意继续浏览 | 从封面进入作品、探索一个系列 |
| 认真看图的访客 | 看清画面、了解背景、不迷失位置 | 查看大图、切换照片、阅读简介、返回原位置 |
| 手机访客 | 分享链接点开就能看，触摸操作自然 | 浏览系列、左右切图、分享某张作品 |

### 2.2 产品目标

1. 通过空间层次、照片运动和连续转场，形成可记住的视觉体验。
2. 保留摄影作品原有的色彩、比例和叙事节奏，作品始终是视觉中心。
3. 访客不学习复杂操作，也能找到作品、打开大图、切换照片和退出。
4. 作者能够通过素材与内容配置更新作品，不必每次修改页面组件。
5. 桌面、手机、低性能环境和减少动态效果设置下，都能完成核心浏览任务。

### 2.3 首版成功标准

| 维度 | 可检验标准 |
| --- | --- |
| 首次理解 | 邀请 3–5 位非开发者试用；至少 80% 无提示完成「进入系列 → 打开照片 → 返回」 |
| 视觉记忆 | 测试者能够描述至少一个招牌交互；无照片拉伸、主要文字遮挡主体等问题 |
| 浏览效率 | 从首页最多 3 次明确点击可打开任一系列中的作品大图；进入作品页后能直接浏览所有作品 |
| 功能可靠 | 本文 P0 验收全部通过，页面无阻断浏览的错误 |
| 作者维护 | 新增一个系列只需补素材与配置，构建后能正确展示，无需改动页面组件 |
| 性能与可访问性 | 达到第 9 节规定的预算和降级要求 |

首版用任务测试与本地性能测量验收；停留时长、访问量等运营指标不作为上线门槛。访客统计后续按需要引入。

## 3. 体验方向与取舍

### 3.1 推荐方向：空间照片舞台 + 编辑式作品集

首页像走进摄影展的入口：5–9 张精选照片沿浅弧形排列，中心作品最大、最清晰，两侧作品逐渐退后。鼠标或触摸拖动照片带，中心作品与标题、序号同步切换。点击当前照片，从原位置展开到大图，观看结束后收回原处。

访客也可以直接点击「浏览全部作品」，进入清楚易用的作品索引。进入某个系列后，照片以大小错落、保留原始比例的版式编排，并穿插少量拍摄故事。

**首版只设置一个空间舞台，不让每个页面都有一套不同的复杂操作。** 其余动画统一围绕「展开、收拢、切换」建立视觉联系。

| 候选方向 | 特征 | 本稿取舍 |
| --- | --- | --- |
| A. 空间摄影展 | 弧形照片带、连续大图转场、策展编排 | 推荐作为首版，兼顾记忆点与作品浏览 |
| B. 纸质翻页画册 | 书脊、纸张、跨页和翻页动画 | 作为后续主题候选；横竖构图混排和手机展示需额外设计 |
| C. 自由漫游 3D 展厅 | 摄像机移动、虚拟墙面、空间导航 | 放入探索阶段；首版不承担三维漫游学习与性能成本 |

以上为产品建议，尚未作为用户最终视觉偏好确认。

### 3.2 视觉基调

- **氛围：** 深色展厅、摄影杂志、安静的空间感。
- **颜色：** 暂用暖黑背景 `#111110`、暖白正文 `#F1EEE7`、灰色辅助文字；只保留一种低饱和强调色。最终值需用真实照片校准并检查对比度。
- **排版：** 大标题、细线分隔、清楚的作品编号、适量留白；中文阅读优先，英文仅作辅助标题。
- **图像：** 已修成片直接展示，不统一添加滤镜、调色遮罩或模糊效果。详情页必须能看完整构图。
- **界面：** 首页少量导航，查看器只保留切图、缩放、信息和关闭等必要控件。
- **文字：** 使用真实系列名称、拍摄地点和简短故事；占位信息必须标明，不编造作者经历、奖项或拍摄参数。

### 3.3 三个标志性交互

| 交互 | 访客感受 | 设计限制 |
| --- | --- | --- |
| 弧形照片带 | 拖动时照片沿弧线转动，当前作品自然来到中央 | 5–9 张封面作品；始终有按钮替代拖拽；有限列表不无限循环 |
| 照片展开与收拢 | 从选中卡片直接展开为大图，关闭后回到原处 | 无法执行连续转场时使用短淡入；返回后保留位置和焦点 |
| 系列浏览节奏 | 标题、照片和说明随自然滚动依次出现 | 不接管整页滚轮，不强制逐屏停留，不设置必须看完的片头 |

## 4. 信息架构与核心流程

### 4.1 页面结构

```text
首页
├─ 精选作品空间舞台
├─ 系列入口
├─ 浏览全部作品
└─ 关于作者

全部作品
├─ 分类筛选
├─ 作品缩略图与基础信息
└─ 单张照片查看器

系列详情
├─ 系列封面、简介与作品数量
├─ 有顺序的照片编排
├─ 单张照片查看器
└─ 下一系列入口

关于作者
└─ 简介与已提供的联系渠道
```

### 4.2 主要用户流程

1. **自由探索：** 打开首页 → 拖动精选照片带 → 点击照片 → 查看大图 → 关闭回到同一张卡片。
2. **按主题欣赏：** 首页选择系列 → 阅读简介 → 顺序浏览 → 打开大图切换作品 → 继续下一系列。
3. **快速找图：** 进入全部作品 → 选择分类 → 打开照片 → 关闭后仍保留分类和浏览位置。
4. **分享作品：** 在大图中复制链接 → 另一浏览器打开 → 直接显示同一照片 → 可关闭查看器继续浏览所属内容。
5. **作者更新：** 准备已修成片和说明 → 生成展示图片 → 更新内容配置 → 本地检查 → 构建发布。

### 4.3 地址与返回规则

- 首版可采用 hash 路由，降低静态托管对服务端重写的依赖；具体路由实现由技术设计确定。
- 示例：`/#/works`、`/#/albums/:albumId`、`/#/albums/:albumId?photo=:photoId`。
- 作品、系列采用稳定 ID，修改标题不改变已有链接；发布后不随意重置 ID。
- 打开查看器会形成可分享状态。浏览器返回优先退出当前查看器，再回到上一级页面；直接访问照片链接时，关闭按钮进入该照片所在的系列或作品列表。
- 从列表打开查看器时，前后切图沿用当前筛选结果与排序；从系列打开时，沿用系列顺序。
- 无效系列或照片链接提供明确说明以及「返回全部作品」，不留下空白页。
- 首版保证链接定位正确；每张照片独立的社交分享预览图属于后续能力。

### 5.1 首版范围之外

首版不做账号系统、评论点赞、社交信息流、在线修图、原片云盘、电商支付或自动 AI 生成照片文案。背景音乐也不纳入首版。

作品图集由作者精选。RAW/HEIC 等原始素材的归档、无损备份和批量选片不属于访客网站职责。

## 6. 页面与交互细则

### 6.1 首页与空间照片舞台

- 首屏显示作者/站点名称、精选作品舞台、「浏览全部作品」和清楚的进入提示。
- 首张照片和主要按钮无需等待全部图片加载，不能被装饰性片头遮挡。
- 初次就绪可执行一次轻量入场：照片从浅错位收拢到弧线；可立即操作，也可跳过。回到首页不重复强制播放。
- 照片舞台固定数量，左右两端有边界反馈；标题、序号和当前照片保持一致。
- 指针水平拖动改变选中照片，释放后吸附至最近位置；开始拖动后不得误触打开照片。
- 桌面鼠标轻微移动可产生有限视差；窗口失焦、离开可视区或减少动态效果开启时停止。
- 滚轮保留页面自然滚动，不映射为强制换图。键盘方向键只在舞台获得焦点时控制舞台。

### 6.2 全部作品与系列详情

- 全部作品采用便于扫视的图片网格，系列采用有叙事顺序的大小错落编排。两者共用作品数据。
- 版式允许横图、竖图、全景图混排；利用已知宽高比预留空间，避免图片加载时页面跳动。
- 若封面需裁切，使用作者指定的焦点；进入查看器后始终显示完整构图。
- 筛选只显示真实存在的分类。切换分类后展示结果数量，并回到结果区域起点；关闭大图时不重置筛选。
- 作品名称与拍摄说明不能仅依赖悬停才出现；手机和键盘同样能够获取。
- 系列结束提供「返回系列目录」及存在时的「下一系列」，明确浏览边界。

### 6.3 单张照片查看器

- 使用视口内适应显示，图片不拉伸；控件与说明占独立区域，不能长期遮住主体。
- 提供上一张、下一张、当前序号、缩放、信息、复制链接和关闭按钮。
- 首尾不循环；首张的上一张、末张的下一张呈禁用状态，并保留可退出入口。
- 信息面板默认收起，展示作品标题、作者提供的地点/日期/故事；未知字段直接省略。
- 点击缩放按钮或双击照片，在适应屏幕和 2 倍之间切换；低分辨率作品不超出其可用像素能力，不能额外下载未配置原片。
- 适应模式下手机水平轻扫切图；放大后拖动只移动图片，切图用明确按钮。缩放、关闭操作不依赖手势。
- 切图后重置缩放与位移；预加载相邻展示图，避免连续操作时反复出现空白。
- `Esc` 关闭；未缩放时方向键切图；`Tab` 在查看器内移动焦点。打开时移入焦点，关闭后回到触发位置。
- 查看器打开时阻止背景滚动。快速切图、关闭、返回或调整窗口大小，不遗留锁滚状态和遮罩。
- 图片失败时保留标题与导航，提供重试，不阻止查看下一张。

### 6.4 手机体验

- 首页保留一张中心照片与两侧预览，轻量横向浏览；不照搬桌面的宽弧线、强透视和多层视差。
- 系列正文采用自然纵向滚动，网格按宽度调整为 1–2 列；查看器兼容横竖屏与系统安全区域。
- 触控照片带优先处理水平手势，页面仍可纵向滚动；不禁用全站浏览器缩放。
- 首屏需有足够明显的浏览入口；所有必要操作无需悬停。

### 6.5 动效规范初值

| 场景 | 建议初值 | 降级方式 |
| --- | --- | --- |
| 控件反馈 | 120–180ms | 保留即时状态变化 |
| 图片和面板切换 | 180–280ms | 短淡入或直接切换 |
| 图卡展开/收拢 | 350–500ms | 取消几何移动，使用淡入 |
| 首次入场 | 不超过 900ms，操作始终可用 | 直接进入静态完成状态 |
| 指针视差 | 平移不超过约 12px、倾斜不超过约 3° | 关闭视差 |

以上是原型调试的起点，不是已经测得的效果。跟随拖动的元素实时响应指针；相同操作采用一致节奏，不叠加长延迟、闪烁或持续自动旋转。

## 7. 内容、照片与作者维护

### 7.1 数据内容

| 对象 | 必需字段 | 可选字段 |
| --- | --- | --- |
| 站点 | 名称、作者显示名、默认语言、首页精选 ID、系列排序 | 简介、联系链接、默认分享图 |
| 系列 | 稳定 ID、名称、简介、封面作品 ID、有序作品 ID 列表 | 年份、展示地点、辅助英文名 |
| 照片 | 稳定 ID、标题、简短 alt、宽高、展示图片路径、分类 | 拍摄日期、地点文本、故事、封面裁切焦点 |
| 图片资源 | 网格图、查看大图及各自尺寸 | 低清占位、更多响应式尺寸、作者选择公开的高分辨率图 |

每张作品可属于多个系列，具体浏览顺序由系列 ID 列表决定；首页精选独立配置。全部作品中的排序由作者统一设定。

### 7.2 素材与更新规则

1. 作者提供已修成片；项目保留交付源文件，展示尺寸另行派生，不覆盖用户原文件。
2. 生成缩略图与查看图，并统一为适合网页展示的色彩空间；不得悄悄改变作品调色。
3. 每张图片记录宽高，输出浏览器可用的压缩格式及兼容格式；具体尺寸与质量通过真实作品测试确定。
4. 增量更新时保留稳定 ID，检查路径、重复 ID、系列引用、标题与 alt。
5. 添加内容后能构建、预览和再次发布；首版允许通过内容文件更新，不提供可视化后台。

建议第一批真实素材：3–5 个系列、30–60 张作品，其中精选 5–9 张；至少包含横图、竖图和一张宽幅作品。实际数量不是页面正常工作的前提。

### 7.3 作品公开策略

- 网页只引用作者选择公开的展示资源，不默认暴露本地源目录或原片下载地址。
- 派生展示图去除 GPS 等不需要公开的元数据；页面地点由作者填写，原文件保持不变。
- 未提供授权与署名信息的素材不混入正式作品集；设计占位图须可识别并在交付前替换。
- 首版不放原图下载按钮。公开展示图片仍可被访客保存，不将禁用右键当作作品保护能力。

## 8. 技术边界与落地原则

本节约束实现方式，不在 PRD 阶段锁定具体框架版本。

- **架构：** 首版采用前端应用 + 静态内容配置，支持静态托管；不依赖数据库或账号后端。
- **空间效果：** 优先验证 CSS transform/perspective 与前端动画能否达到舞台效果；只有样机证明需要时再引入 WebGL。
- **动画：** 统一管理页面转场、照片状态和清理逻辑，避免多套动画系统竞争同一元素。
- **图片：** 构建期生成衍生尺寸；首屏按需加载，其余懒加载；查看器只预取邻近图片，不预载整库高清资源。
- **内容：** 内容配置与表现层分离；路由、筛选和作品标识不依赖当前数组下标。
- **渐进增强：** 空间动画失效或减少动态效果开启时仍可通过平面卡片、按钮和普通网格浏览。
- **部署：** 托管平台、域名及是否需要服务端渲染留至技术设计确定；本次不创建托管资源。

## 9. 非功能需求

### 9.1 性能与加载预算

以下为待实现和验证的目标，不代表现有网站已达到。

| 项目 | 首版目标 | 测试口径 |
| --- | --- | --- |
| 首屏加载 | LCP ≤ 2.5s、CLS ≤ 0.1 | 正式构建；桌面及移动模拟环境各冷启动测量 3 次，记录配置及中位数 |
| 首次进入传输量 | 首页初始请求总量目标 ≤ 2.5MB（压缩后） | 包含脚本、样式、字体和首屏图片；后台预取另行记录 |
| 桌面交互 | 目标接近 60fps，连续操作无明显冻结 | 以 1440×900 普通集成显卡笔记本验证；记录硬件和性能轨迹 |
| 手机交互 | 核心浏览流畅，主要动画目标 ≥ 30fps | 至少一台真实中端手机验证；模拟器不代替真实触摸与内存验证 |
| 大图切换 | 控件即时反馈；有缓存时切图目标 ≤ 200ms | 区分网络等待和动画时间；未缓存图片显示加载状态 |
| 资源释放 | 切换系列/照片不持续累积大图、计时器和监听器 | 连续切图 50 次并关闭重开，检查内存趋势与残留状态 |

上线后的真实 Core Web Vitals 以有足够样本时的第 75 百分位评估，INP 目标 ≤ 200ms；本地实验室指标不冒充线上统计。上述指标阈值参考 [Google Web Vitals 文档](https://web.dev/articles/vitals)。首版没有真实访客数据时不以此阻塞交付。

预算超出时依次减少舞台同时显示数量、关闭视差、简化几何转场；保留看图、导航和分享能力。

### 9.2 可访问性与兼容

- P0 功能可仅用键盘完成；焦点可见、顺序明确，查看器关闭后焦点正确恢复。
- 支持 `prefers-reduced-motion`，同时提供页面内「减少动态效果」开关并在本地记住；开启时取消空间移动、视差和自动入场。
- 普通正文对比度目标至少 4.5:1，大字至少 3:1，参照 [WCAG 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)；控件不能只用颜色表达状态。
- 触摸按钮目标尺寸不小于 44×44 CSS px；图片具有有意义的 alt，纯装饰重复图使用空 alt。
- 核心页面在 360px、390px、768px、1440px、1920px 宽度检查；无意外横向溢出，200% 页面缩放下主要操作可达。
- 浏览器覆盖 Chrome、Edge、Safari 的交付时最新两个主要版本，并验证 iOS Safari 与 Android Chrome。
- 原型阶段确定最低浏览器版本并记录；尚未验证的平台不得标记为已经兼容。

## 11. Stitch 设计协作方案

### 11.1 使用方式

1. 将本 PRD 的定位、核心流程及 8–12 张有代表性的展示图作为设计输入。
2. 探索两个视觉方向：A「深色空间摄影展」、B「暖白编辑式摄影集」。首版推荐 A，B 用于比较照片表现和阅读感受。
3. 选定一个方向后统一页面结构、字体、色彩、网格、图片比例、控件和状态，形成 `DESIGN.md`。
4. 输出桌面与手机关键页面，以及展开前后、加载、错误、减少动态等状态；设计图只描述拖拽过程，不将静态设计当成已实现交互。
5. 使用真实照片制作可运行样机，验证弧形舞台、查看器与手机手势，再扩展全部页面。

Google 官方在 [2025 年 I/O 开发者公告](https://blog.google/innovation-and-ai/technology/developers-tools/google-ai-developer-updates-io-2025/)中介绍 Stitch；[2026 年 3 月更新](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-ai-ui-design/)说明了自然语言设计、交互原型及 `DESIGN.md` 的导入导出。本项目据此规划工作流，不依赖未核实的模型名称、免费额度或使用限制。

### 11.2 可直接使用的设计提示词

> 为一个单作者的个人摄影作品集设计响应式网站。界面语言以中文为主，工作名称为“光的索引 / Light Index”。目标是让访客像进入一座可探索的摄影展，快速感受到作品风格，并能顺畅浏览系列和查看照片细节。
>
> 首先探索深色摄影展方向：暖黑背景、暖白文字、克制的灰色辅助信息、精确的排版和少量细线。照片保持原本色彩；通过大小、空间、留白和顺序形成视觉节奏。使用提供的真实照片，摄影作品是页面主要内容。
>
> 设计桌面 1440px 与手机 390px 的关键页面：首页、全部作品、系列详情、照片查看器、关于作者。首页核心是 5–9 张精选照片形成的浅弧形空间照片带，中心作品突出，两侧逐渐退后；标注左右拖动、选中、点击展开和两端边界状态，并提供明确的替代按钮。手机首页采用更轻量的横向照片浏览。
>
> 全部作品提供真实分类筛选；系列页使用横竖照片混排和简短摄影故事；大图查看器显示完整构图，带切图、缩放、信息、复制链接、关闭和作品序号。展示加载、图片失败、空结果、长中文标题、键盘焦点及减少动态效果状态。
>
> 从照片卡片到大图查看器采用展开与收拢的连续视觉关系。页面滚动自然，入口明确，触摸区域足够大，控件不遮住照片主体。不要添加价格、评论、排行榜或后台界面；不要编造作者经历和奖项。给出统一设计规范，并区分设计示意与需要代码验证的交互。

Stitch 未连接时，仍可使用上述输入制作线框与网页样机。是否采用其导出代码，由可维护性和交互验证结果决定。
